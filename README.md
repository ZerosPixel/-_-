# БУНКЕР — онлайн-версия

Статическая браузерная игра на HTML + CSS + JavaScript. Сборка и npm не нужны.

## Что изменено

### Интерфейс
- Полностью переработан визуальный стиль: тёмный постапокалиптический интерфейс, оранжевый акцент, крупные элементы и компактные карточки.
- Стартовый экран сокращён до коротких правил и пяти этапов: Лобби → Ходы → Обсуждение → Голосование → Финал. Этапы помещаются на экран без горизонтальной прокрутки.
- Убраны технические рекламные/справочные блоки про WebRTC, телефон, ПК и повторные нажатия.
- Лобби разделено на список участников и отдельную панель сценария.
- Кнопки сделаны крупнее и удобнее для нажатия пальцем.
- Рядом с именами игроков показывается уникальный символ, зависящий от устройства игрока, а не первая буква ника.
- Поля ввода используют размер шрифта 16px, чтобы iPhone не увеличивал страницу при вводе.
- Добавлены safe-area отступы и адаптивная раскладка для узких экранов.
- На экране игры информация о катастрофе получила центральную иллюстрацию нормального размера, одинаково подходящую для телефона и ПК.
- Для всех 8 катастроф добавлены отдельные локальные изображения в `assets/`.

### Исправление дублей и соединения
Главная проблема прежней версии была в том, что несколько быстрых нажатий «Войти» могли запустить несколько отдельных PeerJS-подключений. Каждое из них могло получить новый слот с тем же именем.

Теперь:

- кнопка входа блокируется на время подключения;
- у браузера есть постоянный `clientId` в `localStorage`;
- повторный вход с того же устройства возвращает игрока в его прежний слот вместо создания дубля;
- при новом подключении старое соединение этого игрока закрывается;
- при потере соединения слот помечается как отключённый и может быть занят тем же игроком после переподключения;
- добавлена кнопка «Переподключиться»;
- хост может удалить игрока из лобби и освободить его слот;
- одинаковые имена у разных устройств не запрещены: в таком случае хост получает предупреждение, а лишнее подключение можно удалить вручную;
- добавлены STUN-серверы для повышения шанса успешного WebRTC-соединения за NAT;
- есть таймаут подключения с понятным сообщением об ошибке;
- игрок может выйти из комнаты без перезагрузки страницы.

## Что осталось от игровой механики

- 4–15 игроков.
- Все участники играют за персонажей; отдельной роли ведущего нет.
- Комната создаётся сразу с 15 слотами и запускается при любом фактическом составе от 4 до 15 игроков.
- Случайная катастрофа и случайный бункер; для каждой комбинации формируется короткое название комнаты по сценарию, например «Кромешная Тьма».
- 11 безопасных категорий характеристик персонажа.
- В 1-м раунде профессия раскрывается автоматически, затем игрок открывает дополнительные характеристики согласно таблице.
- 2 минуты общего обсуждения.
- 30 секунд речи каждого игрока.
- 2 минуты живого голосования с возможностью менять голос.
- 70% порог, оправдание и повторное голосование.
- Пропуск первого голосования и два исключения в следующем раунде.
- 15-секундная прощальная речь.
- Финальная симуляция учитывает катастрофу, бункер, ресурсы, здоровье, навыки, командную работу и синергию состава.

Очищенный набор контента и правила исходного проекта сохранены.

## Как запустить локально

```bash
python -m http.server 8000
```

Открыть:

http://localhost:8000

Для WebRTC лучше использовать HTTPS при размещении в интернете. Самый простой вариант — GitHub Pages.

## Как опубликовать

1. Создайте репозиторий GitHub.
2. Загрузите `index.html`, `styles.css`, `app.js` и папку `assets/`.
3. Откройте **Settings → Pages**.
4. Выберите публикацию из ветки `main` и папки `/root`.
5. Отправьте друзьям получившуюся HTTPS-ссылку.

Создателю комнаты нужно держать вкладку открытой до конца партии, потому что текущее состояние игры хранится в браузере создателя. В игре нет отдельной роли ведущего: создатель остаётся обычным игроком, а его браузер выполняет техническую функцию синхронизации партии, таймеров и управления комнатой.

## Источник визуального направления

При переработке интерфейса использован как референс подход Bunker Online: атмосферный тёмный экран, заметный статус комнаты, крупные информационные блоки и акцентная кнопка действий. При этом проект остаётся отдельной фанатской реализацией со своим содержимым.

Источник механики: https://bunker-online.com/ru/rules

## Интерфейс характеристик

- Владелец видит все свои значения характеристик до раскрытия; кнопку «Раскрыть» получает только в свой ход и только для ещё закрытых карт, которые можно открыть в текущем раунде.
- На общем игровом поле закрытые значения других игроков отображаются как `???`.
- Перед отправкой состояния другим клиентам скрытые значения и модификаторы удаляются из сетевой копии. Полные карты становятся доступны всем после завершения партии.
- Игровое поле адаптируется к экрану: сетка карточек на компьютере и две колонки на узком экране телефона.
- Во время подключения показывается отдельный экран; игровое состояние не выводится до получения сообщения `state` от комнаты.
